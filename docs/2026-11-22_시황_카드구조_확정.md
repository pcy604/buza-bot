# 시황 구조 확정 — 카드가 단위다

2026-11-22 · 차니 지적 "이런 것들(대시보드 카드) 위주로 되어야 하는 거 아님?"

**맞다. 내 첫 버전이 틀렸다.** 줄글을 쓰고 끝에 숫자 표를 붙였는데,
대시보드는 이미 **카드 단위로 하나씩 완결된 사실**을 들고 있다. 그게 콘텐츠 단위다.

비교:
- v1 `content/sihwang_2026-11-20.json` — 줄글 6문단. 내가 고른 숫자만 들어갔다.
- v2 `content/sihwang_2026-11-20_v2.json` — **카드 7개 = 문단 7개.** 화면에 있는 걸 그대로 옮겼다.

v2 를 쓰면서 v1 에 없던 사실이 쏟아졌다. **글로벌 마켓 카드를 안 봤기 때문이다.**

| v1 에 빠졌던 것 | 값 |
|---|---|
| 필라델피아 반도체 | **−10.7%** (5일 −17.1%) ← 진짜 원인 |
| VIX | 35.89 **+26.2%** (5일 **+86.0%**) |
| 금 · 비트코인 | −4.0% · −5.3% ← 안전자산도 같이 하락 |
| 외국인 20일 | **−15.4조** |
| 신용잔고 | 25.9조 (고점 대비 −23.6%) |
| 특징주 상한가 | 하나에어로 +35.4% · 한진칼우 +30.0% · 타임X AI +30.0% · 쁘아 +29.9% |

**이야기 자체가 바뀐다.** v1 은 "코스피가 빠졌다, 반도체 때문이다" 였다.
v2 는 "미국 반도체가 −10.7% 먼저 무너졌고 VIX 가 하루 +26% 뛰었다. 한국은 받아낸 쪽이다.
그런데 금까지 −4% 빠졌으니 위험회피가 아니라 현금화다. 그 와중에 상한가는 4개 나왔다" 다.

후자가 비교할 수 없이 낫고, **그 재료가 전부 대시보드 화면에 이미 있었다.**

## 1. 1카드 = 1문단 = 1포토카드 = 1숏츠컷

이 네 개를 **같은 객체**로 만든다. 그러면 글·이미지·영상이 따로 놀지 않는다.

```
Content.cards = [
  { card: "글로벌 마켓",   capture: "global_top",   text: "...", say: "..." },
  { card: "시장 폭",       capture: "breadth",      text: "...", say: "..." },
  ...
]
```

- `card` — 어느 대시보드 카드에서 나온 사실인지 (추적용)
- `capture` — 캡처할 화면 영역 키 → 포토카드 PNG · 숏츠 배경
- `text` — 글·자막에 쓰는 문장
- `say` — TTS 발음 (숫자를 한글로: "−10.7%" → "마이너스 십 점 칠 퍼센트")

**지금 `adapt.py` 는 이걸 못 받는다.** `core` 를 글자 수 상한까지 꽉 채워 묶어 버린다.
실제로 v2 를 렌더하니 **글 2에 카드 3개, 글 3에 카드 3개**가 뭉쳤다(각 395자·499자).
카드 구조로 가면 `_chunk` 를 **"카드 하나당 글 하나"** 로 바꿔야 한다. 이게 가장 큰 코드 변경이다.

## 2. 하루 두 판 — 차니가 말한 타이밍이 이미 있다

**`market-report.yml` 이 정확히 그 두 시각에 이미 돌고 있다.** 새로 만들 게 없다.

| 시각(KST) | 요일 | 지금 하는 일 | 추가할 일 |
|---|---|---|---|
| **15:50** | 월~금 | 한국 장 마감 리포트 → `latest_kr` | 한국 마감 시황 발행 |
| **06:30** | 화~토 | 미국 장 마감 리포트 → `latest_daily` | 글로벌 시황 발행 |

(텔레그램 발송은 지금 `daily-refresh`(06:30)에서 `market_report.py daily --telegram` 으로 나간다.
`market-report.yml` 쪽은 `--telegram` 이 없다. SNS 초안을 붙일 자리는 `market-report.yml` 이다 —
두 시각 모두 거기서 돌기 때문이다.)

### 두 판은 성격이 다르다

같은 틀을 두 번 쓰면 안 된다. 보는 사람이 다르고, 쓸 수 있는 카드가 다르다.

| | **15:50 한국 마감판** | **06:30 미국 마감판** |
|---|---|---|
| 보는 사람 | 오늘 장을 본 사람 — "오늘 뭐였지" | 오늘 장을 앞둔 사람 — "오늘 어떻게 되지" |
| 주 카드 | 오늘의 시장 8카드 + 업종 히트맵 | 글로벌 마켓 14카드 |
| 성격 | **정리** | **예고** |
| 규칙 블록 | "오늘 규칙이 뭘 했나"(원장 실적) | "오늘 규칙이 뭘 할 수 있나"(잠금 상태) |
| 숏츠 길이 | 45~50초 (카드 6) | 30~40초 (카드 4~5) |

미국 마감판이 짧은 이유는 아침 7시에 보는 영상이기 때문이다. 길면 안 본다.

### 🔴 먼저 고쳐야 한다 — 캡처가 지금 고장나 있다

`python -m social.shot 005930 --top` 이 2분 기다리다 죽는다.

```
TimeoutError: waiting for locator("text=종목명 또는 코드") to be visible
  225 × locator resolved to hidden <p>종목명 또는 코드</p>
```

11-16 "검색 줄 38px 정렬" 작업에서 라벨이 `label_visibility="collapsed"` 가 됐다
(`dashboard.py:6137` · `ui_cycle.py:31`). 숨은 라벨을 "보일 때까지" 기다리니 영원히 안 온다.

**캡처 없이는 포토카드도 숏츠도 없다. 이게 1순위 작업이다.**
고치는 방법은 라벨이 아니라 **카드 컨테이너**를 기다리는 것이다. Streamlit 카드에
`data-testid` 를 달거나, 카드 제목 텍스트("시장 폭 — 시총", "글로벌 마켓")로 잡는다.
제목은 `label_visibility` 와 무관하므로 안정적이다.

## 5. 자동화 경계 — 어디까지 기계가 쓰나

카드 구조로 가면 **경계가 훨씬 깔끔해진다.** 카드마다 "사실"과 "해석"이 분리되기 때문이다.

| 컷 | 사실 (전자동) | 해석 (사람) |
|---|---|---|
| 1 글로벌 | 필라 −10.7% · VIX +26.2% | — |
| 2 시장 폭 | 84/1,116 · 7% | — |
| 3 히트맵 | 반도체 −6~12% | "미국 폭이 한국 장비로 넘어왔다" 🟡 |
| 4 강한 쪽 | 영화 +0.9% · 상한가 4종 | "좁은 곳으로 몰렸다" 🟡 |
| 5 수급 | 외국인 −15.4조 · 신용 −23.6% | "빚 물량이 정리 중" 🟡 |
| 6 규칙 | 5,300 · +8.8% · 11-16부터 보류 | — (전부 사실) |

**🟡 가 셋뿐이다.** 생성기가 각 칸에 해석 문장을 **1개만 제안**하고, 승인 때 지우거나 고친다.
v1 구조에서는 줄글 전체가 해석과 섞여 있어 이 분리가 안 됐다.

훅은 여전히 반자동이다. 다만 카드 구조에서는 후보가 명확해진다 —
**"오늘 가장 큰 절댓값을 가진 카드"** 가 1순위 훅이다.
11-20 이면 VIX +86%(5일)와 필라 −10.7% 가 자동으로 1·2위로 뽑힌다. 실제로 그게 최고의 훅이었다.

## 6. 그래서 바뀌는 작업 순서

| | 할 일 | 바뀐 점 |
|---|---|---|
| **M0** 🔴 | **`shot.py` 캡처 복구** — 숨은 라벨 대신 카드 제목/컨테이너로 선택자 교체 + 카드별 영역 키 8개 등록 | **새로 1순위.** 이게 없으면 포토카드·숏츠 둘 다 불가 |
| **M1** ✅ | 콘텐츠 숫자 대조 — 완료(4건 수정 필요) | |
| **M2** | 생성기 — `market_report.json` → **카드 배열**로 `content/*.json` 작성. 한국판·미국판 두 템플릿 | 줄글이 아니라 카드 배열을 만든다 |
| **M2b** | `Content` 스키마에 `cards`(card·capture·text·say) 추가 · `title_naver` 추가 | 신규 |
| **M3** | `adapt.py` — **카드 1개 = 글 1개**(묶지 않기) · 네이버 제목·표 · 스레드 목표 280자 · `?src=` | `_chunk` 동작 변경이 핵심 |
| **M4** | 발행 전 검사 — 권유 문구 · 폐기 수치 · 면책 누락 | 그대로 |
| **M5** | 세로 녹화 — 카드별 캡처를 이어 붙이고 히트맵만 스크롤 | M0 가 선행 |
| **M6** | TTS·자막·조립 (`say` 필드 사용) | ffmpeg 설치 후 |
| **M7** | `market-report.yml` 에 초안 적재 단계 추가 (15:50 · 06:30 양쪽) | 크론을 새로 안 만든다 |

**M0 가 1순위로 올라왔다.** 차니가 화면을 보여 준 덕분에 순서가 바뀌었다 —
포토카드가 콘텐츠의 중심이면, 캡처가 고장난 상태로 생성기를 먼저 만들 이유가 없다.

## 7. 남은 판단 하나

**상한가 종목 이름을 그대로 쓸 것인가.**

11-20 특징주 카드에는 하나에어로·한진칼우·타임X AI·쁘아가 상한가로 찍혀 있다.
"오늘 상한가는 이 넷이었다" 는 **사실 기술**이라 규제 문제는 없다(무료 · 불특정 다수 · 단방향).
다만 급등주 이름이 매일 나가면 채널 성격이 "오늘의 급등주 소개"로 굳는다.
그건 우리가 만들려는 브랜드(규칙·검증·정직)와 다른 방향이다.

**제안**: 종목명은 쓰되 **"왜 올랐는지 모른다"를 같이 쓴다.**
"상한가 4종이 나왔습니다. 저는 이 종목들을 분석하지 않았고 제 규칙에도 걸리지 않습니다"
라고 쓰면 사실은 전달하면서 추천으로 읽히지 않는다. 차니 판단이 필요하다.
