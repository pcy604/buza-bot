## 0. 지금 실제 상태 (추측 아님 · 전부 실행해서 확인)

| 항목 | 상태 |
|---|---|

| 시황 원천 | ✅ **매일 자동 생성 중** — `market_report.json` 의 `latest_kr`(11-20 15:45) · `latest_daily`(11-21 11:39), 각각 `markdown` 완성본 + `facts`, 이력 56건 |

**요약: 텍스트 3채널 중 스레드는 오늘 당장 발행 가능하고, 시황은 원천이 이미 완전 자동이다.**

## 3. 계획 자체에 대한 생각 — 구성은 좋다, 순서가 거꾸로다

### 좋은 점

네 가지 주제가 **원천 데이터와 1:1로 붙는다.** 이건 보기보다 큰 장점이다. 소재를 짜낼 필요가 없다.

| 콘텐츠 | 원천 | 자동화 가능성 |
|---|---|---|
| ① 오늘의 시황 | `market_report.json` `latest_kr`·`latest_daily` (매일 자동) | **거의 완전 자동** |
| ② 종목 점검 | 종목 분석 탭 · `stock-deep-dive` 스킬 | 종목 선택만 사람 |
| ③ 주간 포트폴리오 | `live/ledger.json` · `trades.jsonl` | 자동 가능 (단 2번 충돌 해결 후) |
| ④ 퀀트 전략 | `v19_bt.json` · `v19_audit` · `quant_search` | 자동 가능 |

### 문제 1 — 규제 위험이 높은 걸 가장 자주 하게 잡았다

위험도 순서는 이렇다.

```
낮음 ← ① 시황(사실 전달) · ④ 퀀트(방법론) ‖ ③ 포트폴리오(따라하기) · ② 종목 점검(특정 종목) → 높음
```

계획은 **가장 위험한 ②를 주 3회**, 가장 안전한 ④를 주 1회로 잡았다. 거꾸로다.
②는 "특정 종목을 지목해 전망한다" 에 가장 가깝다. 외부 사용자가 생기기 전이라 지금은
조용하지만, 사람이 붙는 순간 가장 먼저 문제되는 게 ②다.

**바꿀 것**: ②를 주 3회 → **주 1회**로 줄이고, 그 자리를 ④(퀀트 방법론)로 채운다.
④는 소재가 마르지 않는다 — `research/` 에 쌓인 실험이 50개가 넘고, 11-22 감사에서만
"워크포워드 4구간 중 3구간", "손익분기 부도율 8%", "비용 1%면 알파 절반" 같은
글감이 세 개 나왔다. **그리고 ④가 제품(대시보드)으로 자연스럽게 연결된다.**

### 문제 2 — 4채널을 한 덩어리로 묶으면 안 된다

물량을 계산해 보면 주 12건 × 4채널 = **48 포스트/주**다. 첫 주에 불가능하고,
무리하면 품질이 깎여서 "꾸준히" 가 2주 만에 끊긴다. 그리고 채널마다 난이도가 완전히 다르다.

| 채널 | 월요일 가능? | 비고 |
|---|---|---|
| **스레드** | ✅ 지금 된다 | 토큰 살아 있음. 텍스트 중심 = 우리 콘텐츠와 가장 잘 맞는다 |
| 네이버 블로그 | 🟡 수동 | `python -m social naver` 로 마크다운 뽑아 붙여넣기. **영구 수동**(쓰기 API 없음) |
| 인스타 | 🟡 토큰 필요 | **이미지가 필수**. 차트 PNG 는 있지만 캐러셀 디자인은 따로 |
| X | 🟡 토큰 필요 | 280자. 한국 주식 콘텐츠의 한국어 독자가 가장 적은 채널 |
| 유튜브 숏츠 | ❌ 불가 | **영상 제작 파이프라인이 0이다.** 아래 참조 |

### 문제 3 — 숏츠는 지금 시작하면 안 된다

솔직하게 말한다. 숏츠는 **텍스트와 다른 제품**이다. 대본·음성·화면·편집·썸네일이 전부 필요하고,
자동 생성한 저품질 숏츠는 노출이 아니라 브랜드 손상이다. 그리고 유튜브는 알고리즘이
"끝까지 보는가" 를 보기 때문에 품질 미달이 채널 자체에 누적 불이익으로 남는다.

**숏츠는 3단계로 미룬다**(아래 로드맵). 대신 지금 할 수 있는 준비가 하나 있다 —
우리는 이미 **12p 딥리포트 카드덱**(stock_studian 브랜드)을 만들고 있다.
그 슬라이드가 그대로 숏츠 화면이 된다. 텍스트 연재를 돌리는 동안 카드덱을
"세로 1080×1920 한 장당 한 문장" 규격으로 쌓아 두면, 나중에 영상화는 조립만 남는다.

## 4. 월요일 발행을 위해 **지금 바로** 할 것

범위를 줄였다. **1채널 + 2주제로 시작한다.** 늘리는 건 쉽고 줄이는 건 어렵다.

### 1주차 범위

```
채널: 스레드 (+ 네이버 블로그 주 1회 수동)
주제: ① 오늘의 시황 — 평일 매일 (월~금)
      ④ 퀀트 전략 — 토요일 1건
합계: 주 6건. 48건이 아니라 6건이다.
```

②종목 점검과 ③주간 포트폴리오는 **각각 2번·3번 항목이 해결된 뒤** 투입한다.

### 차니 몫 (사람만 할 수 있는 것)

| # | 할 일 | 소요 |
|---|---|---|
| **C1** | **1번 결정** — 폐기된 숫자를 (A) 교체할지 (B) 정정 콘텐츠로 만들지 | 5분 |
| **C2** | **2번 결정** — 주간 포트폴리오를 빼는지·뒤집는지·집계만 낼지 | 10분 |
| **C3** | 네이버 블로그 계정에 stock_studian 소개글 1건 선발행(프로필·링크·고정글) | 30분 |
| **C4** | 인스타 `IG_TOKEN` 발급(Meta 앱 → 장기 토큰). 2주차 투입용 | 40분 |
| **C5** | 1주차 글 6건 **승인**. `python -m social approve <id>` — 자동화해도 이 칸은 끝까지 사람이 쥔다 | 매일 2분 |

### 내 몫 (말만 하면 바로)

| # | 할 일 | 왜 지금 |
|---|---|---|
| **M1** | **콘텐츠 20건 전수 숫자 대조** — `results/` 산출물과 맞는지 자동 검사 스크립트. 틀린 건 목록으로 | 1번이 4건만 찾은 거라 나머지 16건이 불안하다 |
| **M2** | **시황 → Content 생성기** — `market_report.json` 의 `latest_kr`/`latest_daily` 를 `content/sihwang_YYYY-MM-DD.json` 으로. hook·numbers·caveat·cta 자동 채움 | ①이 주 5건이다. 손으로 쓰면 첫 주에 끊긴다. **자동화의 첫 조각** |
| **M3** | **발행 전 규제 체크 스크립트** — 단정적 권유·수익률 보장·종목 추천·회원 모집 표현을 정규식으로 잡아 `publish` 를 막는다 | ②③을 넣기 전에 있어야 한다. 11-22 점검에서 "규제가 유일한 빈 자리" 로 나온 것 |
| **M4** | **GH Actions 크론** — 매일 시황 Content 생성 + `draft` 적재 + 텔레그램 미리보기. **발행은 하지 않는다** | 노트북 의존 없이 매일 초안이 쌓인다. 차니는 승인만 |

**M2 → M4 가 끝나면 1주차 운영은 "텔레그램 미리보기 보고 승인 누르기" 로 끝난다.**
하루 2분이다. 그게 "꾸준히" 를 만드는 유일한 방법이다.

## 5. 완전 자동화 로드맵 — 사람이 끝까지 쥘 칸을 먼저 정한다

자동화를 목표로 할 때 제일 먼저 정해야 하는 건 "무엇을 자동화하지 않을지" 다.

```
수집 → 초안 → 규제검사 → [승인] → 발행 → 모니터링 → 개선
 자동   자동     자동      사람      자동     자동      반자동
```

**[승인] 칸은 자동화하지 않는다.** 이유는 세 개다.
① 유사투자자문 — 사람이 보지 않은 투자 문구가 나가면 변명할 수 없다.
② 이 프로젝트의 고질병이 "조용히 틀린 것" 이다. 11-22 에만 세 건 나왔다.
③ 1번 사고(폐기된 숫자)가 자동 발행이었다면 되돌릴 수 없었다.

### 단계

| 단계 | 내용 | 조건 |
|---|---|---|
| **1단계 (이번 주)** | 스레드 1채널 · 시황+퀀트 · 초안 자동 · 승인 수동 | M1~M4 |
| **2단계 (2~3주차)** | 인스타 추가(C4 토큰) · 네이버 주 1회 · 종목 점검 주 1회 투입 | M3 규제검사 통과 필수 |
| **3단계 (4~6주차)** | 발행 성과 수집 자동화(노출·저장·댓글) → 어떤 훅이 먹히는지 숫자로 | 2주 이상 데이터 |
| **4단계 (2~3개월)** | 숏츠 — 카드덱 → 세로 슬라이드 → TTS → 조립. 텍스트가 검증된 뒤에만 | 1~3단계 안정 |
| **5단계** | 성과 피드백으로 훅 자동 선택. **승인 칸은 그대로 사람** | 3단계 데이터 축적 |

**깨지는 지점을 먼저 적는다.** 이 로드맵이 틀어지는 가장 흔한 방식은 "2주차에 채널을
한꺼번에 늘리는 것" 이다. 채널이 늘면 포스트 수가 아니라 **점검해야 할 조합**이 늘어난다
(채널 × 주제 × 이미지 규격). 1채널에서 4주를 버틴 뒤 늘리는 게 빠르다.

## 6. 신경 쓸 네 가지 — 지금 넣을 수 있는 최소 장치

### 후킹

구조는 이미 있다 — `Content.hook` 이 "첫 줄, 스크롤 멈추게 하는 한 문장" 으로 정의돼 있고
플랫폼마다 첫 글에 들어간다. 지금 없는 건 **어떤 훅이 먹혔는지 아는 방법**이다.

지금 할 것: 발행할 때 `slug` 와 훅 유형(숫자형·반전형·질문형·정정형)을 같이 기록해 둔다.
3단계에서 성과와 붙여 본다. **기록이 없으면 4주 뒤에도 감으로 쓴다.**

참고할 만한 외부 공식이 있다(`sergebulaev/threads-skills`, MIT). 다만 영어권 기준이고
"이 종목 사라" 류 훅은 우리가 못 쓴다 — 공식만 읽고 우리 `adapt.py` 규칙에 녹이는 게 맞다.
**스킬로 설치하지 않는다**(유료 중개 서비스 Publora 전제가 따라 들어온다).

### 제품 연결

`cta` · `cta_url` 필드가 이미 있고 대시보드 주소가 박혀 있다. 지금 없는 건 **유입 측정**이다.

좋은 소식: `access.py` 에 이미 `?src=threads|instagram|x|naver|bot` 유입 추적이 들어 있다
(11-15, `usage_events.event='inbound'`). **쓰고 있지 않을 뿐이다.**
지금 할 것: `cta_url` 에 채널별 `?src=` 를 붙이도록 `adapt.py` 를 고친다. 한 줄이다.
그러면 첫 주부터 "어느 채널이 사람을 보내는지" 가 숫자로 남는다.

### 콘텐츠 퀄리티

재고 20건이 있다는 건 품질 기준이 이미 한 번 잡혔다는 뜻이다. 문제는 **매일 나가는 시황**이다.
AI 가 쓴 `markdown` 을 그대로 내보내면 5일 안에 "다 비슷한 글" 이 된다.

지금 할 것: M2 생성기에 **"오늘만 있는 사실 한 개" 를 반드시 넣는 규칙**을 박는다
(`facts` 에서 전일 대비 가장 큰 변화 1개 추출). 시황이 일지가 아니라 관찰이 되게 한다.
그리고 `first-reader` 서브에이전트가 이미 있다 — 발행 전 "배경지식 0인 독자가 막히는 지점"
점검에 쓸 수 있다.

### 고객 소통

**댓글·DM 응답은 자동화하지 않는다.** 투자 질문에 자동 답변이 나가면 그게 바로 자문이다.
자동화할 건 응답이 아니라 **수집**이다.

지금 할 것: 없다. 1주차엔 사람이 직접 읽고 답한다 — 초기 10명의 질문이 제품 로드맵이다.
2단계에서 "어떤 질문이 반복되는지" 를 모으고, 반복 질문은 **답변 자동화가 아니라 대시보드
기능이나 설명서로** 옮긴다. VOC 탭(11-20)이 그 그릇이다.

## 7. 한 장 요약

**월요일에 시작하려면 결정 2개(C1·C2)와 스크립트 4개(M1~M4)면 된다.**
채널은 스레드 하나, 주제는 시황+퀀트, 주 6건이다.

가장 급한 건 자동화가 아니라 **1번(폐기된 숫자)** 이다. 그걸 안 고치고 발행하면
자동화가 잘 돌수록 피해가 커진다.
