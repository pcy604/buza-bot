## 1. 문체 — 숏츠 때문이 아니다. 그냥 내가 잘못 쓴 것이다

**아니다.** TTS 를 염두에 두고 쓴 게 아니다. 핑계를 대지 않겠다.
그리고 더 나쁜 건, **차니가 이미 정해 둔 규칙을 내가 어겼다**는 점이다.

`stock_screener/CLAUDE.md`:

> (2026-11-15 3차) 공개 문구 = **규칙 명세 문체**(명사형·전문 용어).
> 질문형('들어가도 되나?')·구어체·'왜 믿나' 같은 수사 금지.

그리고 지금 텔레그램으로 나가는 Gemini 리포트는 이미 그 문체다 —
"급락을 주도했으며", "투매에 가까운 장세가 나타났다", "동반 순매도하며".
**나만 혼자 다른 문체로 쓴 것이다.**

### 무엇이 유치했나

| v2 (내가 쓴 것) | 문제 |
|---|---|
| "어디서 시작됐는지부터 봅니다." | 구어체. 독자에게 말을 거는 블로그 톤 |
| "눈여겨볼 건 금입니다." | 상투어. 정보가 0인 문장 |
| "한국은 받아낸 쪽입니다." | 비유가 모호하다. 무엇을 받았다는 건지 불명확 |
| "그런데 초록이 없진 않았습니다." | 이중부정 + 색깔로 에두름 |
| "~뜻으로 읽힙니다" | 완충어. 단정도 유보도 아닌 회피 |
| 전 문장이 20자 내외로 균일 | 리듬이 없어 읽으면 또박또박 읊는 느낌이 난다 |

종결어미가 문제가 아니었다. **문장을 구성하지 않고 사실을 한 줄씩 나열한 것**이 문제였다.

### 고친 것 — `content/sihwang_2026-11-20_v3.json`

```
v2  간밤 미국이 먼저 무너졌습니다. 필라델피아 반도체 −10.7%, 나스닥 −5.3%, S&P500 −3.7%.
    공포지수 VIX는 35.89로 하루 +26.2%, 5일로는 +86% 올랐습니다.
    코스피 −5.2%는 이 다음 순서입니다.

v3  간밤 미국 증시가 먼저 무너졌다. 필라델피아 반도체 −10.7%, 나스닥 −5.3%, S&P500 −3.7%.
    변동성지수 VIX는 35.89로 하루 26.2% 상승했고 5일 누적으로는 86% 올랐다.
    코스피 −5.2%, 코스닥 −5.5%는 이 흐름의 연장선에 있다.
```

```
v2  눈여겨볼 건 금입니다. 금이 −4.0%, 비트코인이 −5.3%. 위험자산을 팔고 금으로 간 게
    아니라 금까지 같이 팔렸습니다. 위험회피가 아니라 현금화입니다.

v3  통상적인 위험회피 국면과 다른 지점은 금이다. 금 −4.0%, 비트코인 −5.3%. 주식에서
    빠져나온 자금이 금으로 이동한 것이 아니라 금까지 동반 하락했다. 자산 간 분산이
    작동하지 않는 구간, 즉 위험회피가 아니라 현금화에 가깝다. 200일선 위에 남은 것은
    달러인덱스뿐이다.
```

바꾼 원칙 넷.

1. **평서 종결(~했다·~이다)** — 리포트 문체. Gemini 리포트·사이트 설명서와 같아진다.
2. **용어를 정확히** — '공포지수' → '변동성지수 VIX', '빚으로 산 물량' → '신용융자 잔고'.
3. **문장 길이에 변화** — 짧은 사실 나열 뒤에 긴 해석 문장을 붙여 리듬을 만든다.
4. **완충어 삭제** — "~로 읽힙니다"를 지우고 단정하거나, 근거를 붙여 "~에 가깝다"로 한정한다.

### 숏츠 음성은 어떻게 되나

**자막·글과 음성을 같은 문장으로 쓰지 않는다.** 카드 구조의 `text` / `say` 분리가 이걸 푼다.

| | 쓰는 곳 | 11-20 컷 1 |
|---|---|---|
| `text` | 글·자막 | "간밤 미국 증시가 먼저 무너졌다. 필라델피아 반도체 −10.7%, 나스닥 −5.3%." |
| `say` | TTS | "간밤 미국 증시가 먼저 무너졌습니다. 필라델피아 반도체 마이너스 십 점 칠 퍼센트, 나스닥 마이너스 오 점 삼 퍼센트." |

음성은 `~습니다`가 자연스럽고, 숫자는 한글로 적어야 제대로 읽는다.
**둘을 한 문장으로 쓰려니 어중간해져서 유치해진 것**도 원인 중 하나였다.

## 2. 제품 링크 — 담백하게, 맨 끝에

지금 v3 의 마지막 두 블록은 이렇게 나간다.

```
[본문 ... 한계 ...]

오늘 수치의 원본 화면
https://stock-dashboard-dmfvhcig7brge7utl7et5r.streamlit.app/

본 내용은 과거 데이터의 정리이며 특정 종목의 매수·매도 권유가 아닙니다.
투자 판단과 책임은 본인에게 있습니다.
```

v2 의 CTA 는 "위 숫자는 전부 대시보드 🏠 종합 탭과 글로벌 마켓 카드에서 매일 갱신됩니다"
였다. 설명이 길고 홍보처럼 읽힌다. **v3 은 "오늘 수치의 원본 화면" 일곱 글자다.**
본문 숫자를 다 보여 준 뒤라 더 말할 필요가 없다.

플랫폼별로는 이렇게 다르게 나간다.

| 플랫폼 | 처리 |
|---|---|
| 스레드 | 링크를 **답글 체인 뒤쪽**에 둔다(첫 글에 링크를 넣으면 도달이 깎인다). 지금 구조가 이미 그렇다 |
| 인스타 | 본문 링크가 클릭되지 않는다 → "프로필 링크" 안내로 치환 필요(M3) |
| 네이버 | 본문 맨 아래 한 줄. 검색 유입이 목적이라 이게 가장 효과가 크다 |
| 숏츠 | 영상에는 링크를 넣지 않는다. **설명란 첫 줄**에 둔다 |

링크에 `?src=threads` 같은 채널 표시를 붙인다. `access.py` 에 유입 추적이 이미 들어 있고
(11-15, `usage_events.event='inbound'`) 쓰지 않고 있을 뿐이다. 붙이면 첫 주부터
어느 채널이 사람을 보내는지 숫자로 남는다.

## 3. 토큰 안 쓰고 완전 자동화 — 된다. 단 조건 셋

**"내(Claude) 토큰"이 드는 건 만들 때뿐이고, 돌 때는 안 든다.**
근거: 지금 텔레그램으로 나가는 시황 리포트가 이미 그렇다. `market-report.yml` 이
Gemini 로 매일 두 번 글을 쓰고 커밋한다. **이력 56건, 내 개입 0.**

### 플랫폼별 판정

| 플랫폼 | 완전 자동 | 방식 | 내 토큰 | 막히는 지점 |
|---|---|---|---|---|
| **스레드** | ✅ | Graph API · 토큰 **지금 살아 있음**(`stock_studian` 확인) | 0 | 60일마다 토큰 갱신 |
| **인스타** | ✅ | Graph API | 0 | `IG_TOKEN` 미설정 · **이미지 필수** · 60일 갱신 |
| **X** | ✅ | API v2 · 코드 있음 | 0 | 키 4개 미설정 · Free 티어 **월 1,500건** |
| **유튜브 숏츠** | ✅ | Data API v3 (OAuth refresh token) | 0 | 영상 조립이 선행 · ffmpeg 필요 |
| **네이버 블로그** | ⚠️ | Playwright 브라우저 자동화 | 0 | **노트북에서만** · 캡차 · 약관 회색 |

**다섯 중 넷은 서버에서 무인으로 돈다.** 네이버만 성격이 다르다.

### 글은 누가 쓰나 — 세 층

```
① 숫자·사실     market_report.json · 원장           → 기계. 비용 0
② 문장           Gemini 2.5 Flash (이미 쓰는 중)      → Gemini 토큰. 내 토큰 0
③ 훅 선택·해석   사람이 승인 때 고름                  → 2분
```

②가 핵심이다. **Gemini 가 쓴다. 내가 안 쓴다.** `GEMINI_KEY` 는 이미 Actions 에
들어가 있고 한 달 넘게 돌고 있다. 비용은 Gemini 요금이고 Flash 모델이라 시황 한 건에
사실상 무시 가능한 수준이다.

### 막히는 지점 셋 — 숨기지 않고 적는다

**① 네이버는 영원히 노트북이다.**
데이터센터 IP(Actions 러너·VPS)에서 네이버에 로그인하면 거의 확실히 차단된다.
가정용 IP 가 필요하다. 즉 **네이버만은 노트북이 켜져 있어야 돈다.**
11-10 처럼 노트북이 꺼진 날은 네이버만 빠진다. 나머지 넷은 영향 없다.

**② 토큰 60일 만료는 사람이 해야 한다.**
Threads·Instagram 장기 토큰은 60일마다 갱신이다. `python -m social refresh` 가
새 토큰을 화면에 찍어 주지만 **.env 와 GitHub Secrets 에 넣는 건 사람**이다.
→ 만료 7일 전에 텔레그램으로 알리는 단계를 넣어야 한다. 안 넣으면 어느 날 조용히 멈춘다.
이 프로젝트에서 가장 흔한 고장 유형이 정확히 이거다.

**③ 승인을 없애면 완전 무인이 되지만, 권하지 않는다.**
기술적으로는 `approve` 를 건너뛰고 바로 `publish` 하면 된다. 하지만:

- 오늘 찾은 것만 해도 재고 콘텐츠 4건이 **폐기된 수치**(20.7%)를 들고 있었다.
  자동 발행이었으면 이미 나갔다.
- 투자 문구가 사람 검토 없이 나가는 건 규제 쪽에서 가장 변명하기 어려운 모양이다.
- 승인은 텔레그램 버튼 한 번이고 **내 토큰이 들지 않는다.** 비용이 0인 안전장치를
  굳이 뺄 이유가 없다.

### 결론

| 질문 | 답 |
|---|---|
| Claude 토큰 없이 매일 자동 발행 되나 | **된다.** 만들 때만 쓰고 돌 때는 안 쓴다 |
| 스레드·인스타·X·숏츠 | **된다.** 전부 API. 서버에서 무인 |
| 네이버 블로그 | **된다. 단 노트북에서만.** 공식 API 가 2020년에 없어졌다 |
| 사람이 꼭 해야 하는 것 | ① 60일마다 토큰 갱신 ② 하루 2분 승인 |

**지금 비어 있는 건 코드가 아니라 자격증명이다.**
스레드는 이미 살아 있고, 인스타·X·유튜브는 토큰만 넣으면 코드가 돈다.
