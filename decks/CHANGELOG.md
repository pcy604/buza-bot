# 16p 딥리포트 — 개선 히스토리

이 파일은 포토카드 렌더러(`deck_pages.py`/`charts2.py`/`deck16.py`/`sources.py`/`autogen.py`)에
가해진 변경을 기록한다. **공용 코드 수정**(다음 항목에 표시 없으면 전부 해당)은 이미 렌더된 종목
포함 전 종목에 자동 적용됨 — 재렌더만 하면 됨. **데이터 수정**은 그 종목 파일에만 해당.

IONQ를 시험대 삼아 자동생성 파이프라인을 처음부터 실전 검증한 세션(2026-08-02) — 아래 항목 대부분
이 이 과정에서 나옴.

## 2026-08-07 (2차) — "아무 종목이나 넣어도 되냐"에 대한 실측 답

1차에서 검증한 건 전부 **이미 데이터 파일이 있던 종목**(PLTR·IONQ)이었다. 진짜 질문은
처음 보는 종목이 들어와도 되느냐다. 파이프라인의 데이터 수집 절반은 LLM을 안 쓰므로
쿼터 없이 넓게 찔러볼 수 있어서, 업종·공시형태가 다른 종목들로 실측했다. 세 가지가 깨졌다.

**신규 `probe.py` — LLM 0콜 사전 점검.** `python probe.py NVDA JPM O TSM`
autogen은 Gemini 무료 쿼터를 8콜 쓴다. 8콜 다 태우고 나서 "빈 표만 나오네"를 알면 그날
쿼터가 날아간다. EDGAR·Yahoo만 찔러 **OK / PARTIAL(뭐가 빌지 목록) / NO(이유)** 를 먼저
말해준다. `autogen.py`가 시작할 때 자동으로 돌려서, 지원 불가면 LLM 호출 0회로 중단한다
(실측: `python autogen.py 005930` → 쿼터 소모 없이 즉시 차단).

**결함 ① 은행·리츠는 영업이익 태그를 아예 안 낸다.** JPM·O 실측 — `OperatingIncomeLoss`
전 연도 없음, `NetIncomeLoss`는 정상. 그런데 파이프라인이 이걸 "영업이익 0"으로 받아서:
- CANSLIM C·A가 **둘 다 0점**(JPM 같은 초우량 흑자기업이 50점 만점에 0점)
- 8p 밸류에이션이 `"최근 분기 적자라 PER이 정의되지 않음"`이라는 **사실과 정반대 문장**을
  붙임 — JPM은 적자가 아니라 태그가 없을 뿐이다.

`_profit_series()` 신설 — 영업이익이 원칙, 없으면 순이익으로 대체하고 차트 제목·범례
라벨도 같이 바뀐다. PBR 대체 사유도 "적자라서"와 "이익 태그가 없어서"를 구분해서 쓴다.
실측 검증: JPM C 0점 → **25점**, A 0점 → **2.3점**(순이익 기준), PLTR은 영업이익 그대로 변화 없음.
그 김에 손익계산서에 **순이익 행 신설** — 예전엔 영업이익만 있어서 은행·리츠는 손익계산서에
이익 숫자가 한 줄도 안 남았다.

**결함 ② 외국기업(20-F)은 재무가 통째로 비었다.** TSM 실측 — `us-gaap` 태그 0개,
`ifrs-full` 334개. `annual_series`가 `facts['us-gaap']`만 보고 있어서 재무3표·밸류에이션·
CANSLIM이 전부 빈 채로 나왔다. `IFRS_TAGS` 매핑(20개 항목) 추가 + `_taxonomy_facts()`로
두 택소노미를 병합(회사는 둘 중 하나만 쓰므로 충돌 없음). TSM 판정 **NO → PARTIAL**,
재무 8개년(2017~2024) 확보.

**결함 ③ (잠재) 외화를 USD인 척 쓰고 있었다.** `_pick_unit`이 USD가 없으면
`list(units.values())[0]`로 아무 통화나 집어왔다 — TWD·EUR 매출을 USD 시가총액으로 나누면
PSR·PER이 통째로 틀린 숫자가 된다. USD 계열이 없으면 아예 비우도록 바꾸고(틀린 숫자보다
"데이터 없음"이 낫다), probe가 이 경우를 "보고통화가 USD가 아님"으로 미리 알려준다.

**probe 자체의 오탐 1건도 수정** — `filing_history(limit=40)`로 DEF 14A를 찾으니 대형주는
8-K·Form 4가 워낙 많아 NVDA·JPM·O·MRNA 전부 "위임장 없음" 오탐이 났다. autogen이 실제로
쓰는 방식(submissions 전체 목록)과 똑같이 확인하도록 수정.

### 실측 커버리지 — 19종목 직접 probe (2026-08-07)

"미국 주식이면 다 되냐"에 추측이 아니라 실측으로 답하기 위해, 업종·공시형태·상장시점이
다른 19종목을 전부 돌렸다.

| 판정 | 종목 | 비고 |
|---|---|---|
| **OK** | NVDA · MRNA · RKLB · RDDT · LUNR · SMCI · PLTR · IONQ | 전 페이지 정상 |
| **OK** | BRK-B | 티커에 하이픈 있어도 조회 정상 |
| **OK** | JPM(은행) · O(리츠) | 영업이익 태그 없음 → 순이익 자동 대체 |
| PARTIAL | TSM · ARM · SHOP · BABA | 외국기업 — 재무는 확보, DEF 14A가 없어 4p 경영진·RSU·내부자지분이 빔 |
| PARTIAL | CRWV | 상장 18개월 — CAGR 대신 누적수익률, 퀀트 히트맵이 얇음 |
| PARTIAL | VKTX | 무매출 개발단계 — PSR·GPM·부문별매출이 전부 의미 없음 |
| **NO** | SPY · QQQ | ETF는 10-K를 안 냄 — 애초에 기업분석 대상이 아님 |
| **NO** | TM(도요타) | XBRL이 JPY만 — USD 시총과 단위가 안 맞아 사용 불가 |
| **NO** | 005930 | SEC 미등록 |

이 과정에서 probe 자체 버그도 하나 나왔다 — **매출 0을 "매출 태그 없음"으로 오판**해
VKTX를 통째로 차단했다(`if v`로 걸러 0이 falsy 처리됨). 0과 None은 완전히 다른 사실이고,
이 프로젝트에서 반복해서 나온 버그 클래스다(차트 유령 0-막대, 히트맵 None 표시 등).
`is not None`으로 수정하고 "전 기간 매출 0(개발단계 기업)"이라는 별도 안내로 바꿈.
`_score_canslim_n`의 같은 패턴에도 주석으로 못박아둠.

**남은 구조적 한계**: ① 한국·기타 해외 거래소(SEC가 원천이라 불가) ② USD를 공시하지 않는
외국기업(TM) ③ ETF·지수 ④ 외국기업의 4p — 위임장 제도 자체가 없어 원천이 없음
⑤ 무매출 기업은 렌더는 되지만 매출 기반 페이지가 비어 발행 품질이 떨어짐(별도 템플릿 필요).

## 2026-08-07 — "고쳤는데 다음 종목에서 또 나온다"의 구조적 원인 제거

문제 제기: *"수정요청한 게 그 다음 종목으로 돌릴 때 똑같이 문제로 발생하고, 똑같은 얘기를
계속 반복하고 있다. 이것 때문에 SNS 업로드도 못 하고 있다."* — 맞는 진단이었고, 원인은
셋이었다.

**원인 ① 고친 자리가 "종목별 데이터 파일"이었다.** IONQ의 RSU, AAPL의 창업연도, PLTR의

**원인 ② 공용 렌더러에 연도·해석이 리터럴로 박혀 있었다.**

| 위치 | 박혀 있던 것 | 어떻게 깨졌나 | 수정 |

**원인 ③ autogen이 매번 같은 자리를 비운 채 넘겼다.** → 자동 채움으로 전환:
- `CANSLIM_N` 5개 항목 자동 채점(`_score_canslim_n`) — 탑티어=동급 경쟁사 대비 시총 순위,
  성장연수=컨센서스 20%+ 성장 연수(+과거 3년 CAGR≥20%면 +1), 신시장CAGR=TAM 헤드라인의
  CAGR, 지배구조=위임장 근거 있을 때만. **각 항목의 근거 문장을 카드에 같이 찍는다**
  (점수만 있고 근거가 없으면 지어낸 것과 구분이 안 되므로). PLTR 실측: N 0점 → 17점.
- `LEADERSHIP.people` — 위임장 발췌 키워드에 `Chief Financial Officer`·`Executive Officers`
  추가 → 4p "주요 경영진" 표가 처음으로 채워짐(전 종목 영구히 빈 배열이던 것).
- `TAM.label`(항상 빈칸이었음), `SHARES.note`·`SEGMENTS.note`의 검수용 문구 제거.
- 상장연도: **실제 시세 시작연도를 1순위로** — PLTR 실측에서 10-K 추출값이 2011(실제 2020
  NYSE 직상장)이라 "2011년 상장·16년차" 타일과 2020부터 시작하는 차트가 같은 페이지에서
  모순됐다. SEC formerNames 기반 `listing_date`도 시세와 1년 넘게 어긋나면 버린다.

**신규 — 발행 전 품질 게이트 `check.py`** (`build.py`가 렌더 후 자동 실행)
사람이 12장을 눈으로 훑어야만 빈 항목·자리표시자를 발견하던 구조 자체가 반복 지적의 원인이라,

- 금액을 `"1.5억 달러"`로 표기 — $1.5B는 15억 달러다. **같은 카드의 표와 숫자가 어긋남**

**렌더 결함(전 종목 공통) 수정**

  섹션이 쓸 높이를 빼고 남는 만큼만 표에 할당, 잘리면 "(공시 N명 중 상위 M명)" 명시.

확인, SATL·TSLA·IONQ·AAPL·SNDK 재렌더로 회귀 없음 확인. 기존 5종목은 이번 규칙 이전에

재생성하면 해소된다(LOCKED 덕에 손으로 넣은 값은 유지됨).

## 페이지별 설계 변경 (템플릿 반영, 향후 종목 공통 적용)

- **CANSLIM**: 총점 배지 각진 사각형으로 통일(둥근모서리+각진 액센트바 겹침이 "오려붙인" 시각버그

## 2026-08-02 5차 — 연혁 차트·CAGR·체크포인트·MDD 조회기간 사용자 피드백 반영

**연혁 페이지 CAGR이 실제로 틀려있었다.** 라벨은 "1980년 상장 종가 대비"인데 실제
계산은 1997년부터였음 — `_listing_date_from_sec`가 SEC formerNames의 (날짜순 정렬도
안 된) 리스트 마지막 항목을 상장일로 채택하는데, AAPL의 그 항목은 "APPLE COMPUTER
INC/ FA"라는 1997년의 하루짜리 행정상 별칭이었음(SPAC 합병 감지용으로 만든 로직이
오래된 회사의 일반 개명 이력에 오작동). formerNames가 여러 번(=복잡한 개명 이력)이면
이 휴리스틱 자체를 안 믿도록 수정 + AAPL 실제 IPO일(1980-12-12)로 직접 교체 →
CAGR +119%/년(틀린 기간 기준) → +77%/년(올바른 기간 기준)으로 정정.

**차트의 급등락 배지(1·2)가 "애플 역사에 대해 아무것도 알 수 없는" 구간을 가리켰다.**
자동탐지가 등락'률'만 기준으로 전체 이력을 훑다 보니 2000년대 초 닷컴버블 시기
(주가가 몇십 센트 수준이던 시절)의 노이즈가 등락률상 1등이었음 — `_detect_price_moves`
를 최근 20년으로 제한하도록 수정, 실제로 유명한 구간(2019~20 서비스+코로나 랠리
+198%, 2008 아이폰3G 우려 급락 -53%)이 나오게 됨. **덤으로 발견한 별도 버그**: 이유
생성 프롬프트(`PRICE_MOVE_PROMPT`)가 애초에 JSON 출력을 요구한 적이 없어서, LLM이
멀쩡한 이유를 답해도 파싱이 항상 실패해 "단일 계기 미확인"으로만 떨어졌음(다른 프롬프트는
전부 JSON 요구인데 이것만 빠져있었음) — JSON 스키마 추가로 해결. 이 버그는 다른
종목의 과거 급등락 이유에도 똑같이 영향을 줬을 가능성이 있음.

**체크포인트 타임라인 "시점" 라벨이 "…"로 잘림** — "미국 대법원 판결 (Epic Games)"처럼
사건 설명을 시점 칸에 통째로 넣어서 생긴 문제(제목 칸과 중복이기도 함). AAPL 데이터를
"대법원 판결시"처럼 순수 타이밍만 남기게 수정 + RECENT_PROMPT에 "10자 이내, 사건
설명 넣지 말 것" 규칙 추가(향후 자동생성 종목 재발 방지).

**월간 퀀트·MDD가 항상 "6년"만 보여줬다** — 오래된 종목(AAPL)에서 역사적 낙폭·계절성
패턴을 거의 못 봤다는 지적. MDD(낙폭 라인차트)는 수십 년을 한 선으로 그려도 문제없어
30년으로 확장(AAPL 실측: 1997~2026, 닷컴버블·금융위기 낙폭 다 보임). 히트맵(연도×월
표)은 한 해가 한 행이라 그대로 30년 넣었더니 페이지가 통째로 푸터 밖으로 넘쳤음(첫
시도에서 발견, 노트박스가 푸터와 겹침) — 표 형식 자체가 수십 년을 한 페이지에 못
담으므로 8년으로 절충(원래 6년보다는 늘어남). "MDD N년" 푸터 라벨도 처음엔 "요청한
연수"(예: 30)를 그대로 찍어서 실제 데이터가 5~6년뿐인 어린 종목(IONQ)에서 "MDD 30년"
이라는 거짓 라벨이 뜨는 회귀가 있었음 — series 타임스탬프에서 실제 기간을 직접 재도록
수정.

**차트가 안 예쁘다는 지적** — 로그축 종목의 y축이 "$345 / $5 / $0.06"처럼 눈금 3개만
뜬금없이 떠 있어 가격 감이 안 잡혔음. 1·2·5 배수의 "깔끔한" 가격 레벨(예: $0.1·$1·$10·
$100)마다 실제 눈금선+라벨을 긋도록 교체 — 로그차트답게 보이고 가독성도 좋아짐. MDD
차트도 30년으로 늘리며 연도 라벨이 다닥다닥 겹치는 회귀가 났었는데(1997 1998 1999...가
전부 붙어보임 + 그 아래 문장까지 침범) 폭에 맞춰 라벨을 솎아내도록(세로 구분선은 유지)

  서식(글자·색·박스 위치)은 내가 직접 고치고 싶다"는 요청에 대응. `python pptx_export.py

- **설계**: `deck_pages.py`의 12개 페이지 함수는 원래 `deck16.new_canvas()`가 돌려주는
  draw 프록시(SDraw)에만 그림 — 이 프록시를 PPTXDraw(pptx 네이티브 도형을 만드는 버전)로
  바꿔치기하면 페이지 레이아웃 코드를 한 줄도 안 건드리고 그대로 재사용된다(모듈 함수는

  기존 PNG 렌더 코드와 별개 사본을 만든 게 아니라 **같은 코드가 두 백엔드로 그리는 구조**라
